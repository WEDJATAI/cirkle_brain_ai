   201→# 4. WEDJAT BRAIN CONSTITUTION
   202→
   203→The following rules are mandatory and override convenience.
   204→
   205→## Rule 1 — No false intelligence claims
   206→
   207→Do not claim that Wedjat trained its underlying model when the system merely:
   208→
   209→* stored memory
   210→* added documents
   211→* updated prompts
   212→* changed retrieval
   213→* changed routing
   214→* changed tool policies
   215→
   216→Use accurate terminology.
   217→
   218→---
   219→
   220→## Rule 2 — Model output is not automatically truth
   221→
   222→Never automatically convert:
   223→
   224→```text
   225→LLM output
   226→```
   227→
   228→into:
   229→
   230→```text
   231→verified knowledge
   232→```
   233→
   234→unless independent evidence or an explicit validated workflow justifies doing so.
   235→
   236→---
   237→
   238→## Rule 3 — Authorization is outside the model
   239→
   240→The model may request an action.
   241→
   242→The policy/authorization layer decides whether that action is permitted.
   243→
   244→---
   245→
   246→## Rule 4 — Retrieved content is untrusted
   247→
   248→Documents, websites, emails, tool results, user-provided text, and external data may contain malicious instructions.
   249→
   250→They must never be treated as system-level instructions.
   251→
   252→---
   253→
   254→## Rule 5 — Tenant isolation is mandatory
   255→
   256→The Brain must never leak:
   257→
   258→* memories
   259→* documents
   260→* knowledge
   261→* conversation information
   262→* tools
   263→* data
   264→* credentials
   265→* hidden metadata
   266→
   267→between unauthorized tenants, users, applications, or organizations.
   268→
   269→---
   270→
   271→## Rule 6 — Side effects require explicit authorization
   272→
   273→A model recommendation is not execution.
   274→
   275→Distinguish:
   276→
   277→```text
   278→recommendation
   279→draft
   280→simulation
   281→requested action
   282→authorized action
   283→executed action
   284→verified result
   285→```
   286→
   287→---
   288→
   289→## Rule 7 — Important knowledge has provenance
   290→
   291→The Brain must be able to determine:
   292→
   293→```text
   294→where did this information come from?
   295→when was it obtained?
   296→what evidence supports it?
   297→what version was used?
   298→is it still valid?
   299→does conflicting evidence exist?
   300→```
   301→
   302→---
   303→
   304→## Rule 8 — Knowledge is temporal
   305→
   306→The Brain must distinguish:
   307→
   308→```text
   309→current
   310→historical
   311→future/scheduled
   312→expired
   313→unknown
   314→conflicted
   315→```
   316→
   317→---
   318→
   319→## Rule 9 — Learning is controlled
   320→
   321→Production activity may generate:
   322→
   323→```text
   324→learning candidates
   325→```
   326→
   327→It must not silently modify trusted knowledge, prompts, policies, or model behavior.
   328→
   329→---
   330→
   331→## Rule 10 — Simplicity wins unless complexity is justified
   332→
   333→Do not introduce:
   334→
   335→* another database
   336→* another vector database
   337→* another queue
   338→* another gateway
   339→* another microservice
   340→* another cache
   341→* another orchestration system
   342→
   343→without a measurable reason.
   344→
   345→---
   346→
   347→## Rule 11 — Logical modularity does not require microservices
   348→
   349→Implement strong boundaries in code first.
   350→
   351→Create physically independent services only when justified by:
   352→
   353→* scale
   354→* security
   355→* deployment independence
   356→* reliability
   357→* performance
   358→* organizational ownership
   359→
   360→---
   361→

   363→
   364→Nothing is “done” because code exists.

   366→A capability is done only when:
   367→
   368→```text
   369→implemented
   370→+
   371→tested
   372→+
   373→secured
   374→+
   375→observable

   966→
   967→  state?: {
   968→    actionStatus?: "none" | "proposed" | "authorized" | "executed";
   969→  };
   970→
   971→  quality?: {
   972→    evidenceStatus:
   973→      | "verified"
   974→      | "supported"
   975→      | "inferred"
   976→      | "uncertain"
   977→      | "conflicted"
   978→      | "unsupported";
   979→  };
   980→}
   981→```
   982→
   983→Do not expose internal-only fields unless appropriate to the product.
